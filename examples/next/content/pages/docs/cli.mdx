# Ligne de commande

`@figatellu/cli` installe la commande `figatellu`. Lancez-la à la racine du projet, là où se trouve `figatellu.config.ts`.

## Les commandes

| Commande            | Rôle                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `figatellu build`   | Analyse le contenu et écrit le code généré dans `.figatellu/`.                            |
| `figatellu check`   | La même analyse, sans rien écrire : pour l’intégration continue.                          |
| `figatellu watch`   | Construit, puis reconstruit à chaque changement du contenu, de la config ou des messages. |
| `figatellu search`  | Indexe le site construit avec Pagefind, un index par langue.                              |
| `figatellu migrate` | Déplace le contenu vers une autre langue par défaut ou une autre notation.                |

```sh npm
npx figatellu build
npx figatellu watch
```

```sh pnpm
pnpm figatellu build
pnpm figatellu watch
```

```sh yarn
yarn figatellu build
yarn figatellu watch
```

```sh bun
bunx figatellu build
bunx figatellu watch
```

## Les options

| Option                  | Effet                                                                                                                                        |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `-c`, `--config <path>` | Le fichier de config (`figatellu.config.ts` par défaut).                                                                                     |
| `-m`, `--mode <mode>`   | `production` (par défaut pour build et check) exclut les brouillons et le contenu de test ; `development` (par défaut pour watch) les garde. |
| `--site <path>`         | search : le HTML construit.                                                                                                                  |
| `--out <path>`          | search : où écrire les index (`public/pagefind` par défaut).                                                                                 |
| `--locale-folders`      | search : chaque langue est construite dans son propre dossier, celle par défaut comprise.                                                    |
| `--write`               | migrate : applique le plan.                                                                                                                  |

## Les codes de sortie

| Code | Sens                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| `0`  | Aucune erreur.                                                                |
| `1`  | Des erreurs de contenu, chacune signalée avec son fichier.                    |
| `2`  | Une config invalide ou une erreur d’usage, l’aide affichée après le problème. |
| `3`  | Un échec inattendu.                                                           |

## La surveillance

`watch` exécute ses builds un par un : un changement pendant un build l’annule et en lance un nouveau, et le dernier code généré valide reste en place jusqu’à ce que le nouveau réussisse. Il s’arrête proprement sur Ctrl+C ou SIGTERM.

## Les migrations

`migrate` change la langue par défaut, ou la notation (dossiers de langue implicites ou explicites). Sans `--write`, il affiche son plan ; avec, il déplace chaque fichier, modifie la config et écrit `redirects.json`, tout ou rien :

```sh npm
npx figatellu migrate default-locale en
npx figatellu migrate default-locale en --write
```

```sh pnpm
pnpm figatellu migrate default-locale en
pnpm figatellu migrate default-locale en --write
```

```sh yarn
yarn figatellu migrate default-locale en
yarn figatellu migrate default-locale en --write
```

```sh bun
bunx figatellu migrate default-locale en
bunx figatellu migrate default-locale en --write
```

Les redirections se composent avec les précédentes : un ancien lien atteint sa page en un seul saut, quel que soit le nombre de migrations.
