# Messages

Les textes de l’interface vivent dans des fichiers de messages, un par langue. figatellultimate en déduit une partie du contenu lui-même : un dossier ou un tag ajouté exige sa traduction partout.

## Le squelette généré

Chaque dossier déclare ses champs, comme un `title`, et chaque terme de taxonomie les siens, comme un `label`. figatellultimate les rassemble en un squelette : `content.blog.news.$.title`, `taxonomies.tags.release.label`. Le `$` sépare les champs d’un dossier de ses sous-dossiers.

## Le schéma de l’application

`messages.schema` nomme un module qui étale le squelette, puis ajoute vos propres clés, laissées vides :

```ts
import { skeleton, type MessageSchema } from '#figatellultimate/messages';

const _ = '';

export const schema = {
  ...skeleton,
  ui: { toc: { title: _ } },
} as const satisfies MessageSchema;
```

Le schéma s’écrit une fois ; chaque langue en tire son type.

## Une langue par fichier

`messages/fr.ts` et `messages/en.ts` remplissent ce schéma, et chacun doit le satisfaire exactement. Une clé oubliée, ou une clé de trop, ne compile pas, et `figatellultimate check` nomme la clé et le fichier à compléter.

## Les clés inutilisées

`figatellultimate build` et `check` signalent chaque clé de votre schéma qu’aucun code n’utilise plus, pour qu’un texte mort cesse d’être traduit dans chaque langue. Une clé compte comme utilisée là où vous l’écrivez, en littéral ou en gabarit, à un endroit typé comme clé de message : `t('ui.toc.title')`, ``t(`ui.sort.${sort}`)``, un traducteur restreint à un sous-arbre, ou votre propre fonction typée. Les clés du contenu ne sont jamais signalées : elles suivent les dossiers.

Pour garder une clé que rien ne lit dans l’application, dites pourquoi au-dessus d’elle dans le schéma ; le commentaire garde aussi un groupe entier :

```ts
ui: {
  // figatellultimate-keep: lu par les modèles d’e-mail
  legacy: { title: _ },
},
```

`check` lit les types de l’application : il lui faut un `.figatellultimate/` à jour, sinon il indique qu’il n’a pas vérifié (lancez `figatellultimate build`). Les deux ont besoin d’un `tsconfig.json` à côté de la configuration.

## Les messages ICU

Les messages suivent ICU. figatellultimate les analyse tous, exige pour chaque langue les catégories de pluriel dont elle a besoin (`few` en polonais, `other` partout), et type les arguments : un message avec `{count, plural, …}` prend un nombre, et l’oublier ne compile pas. Chaque langue doit prendre les mêmes arguments que la langue par défaut.

```ts
folder: { more: '{count, plural, one {Voir le billet} other {Voir les # billets}}' },
```

## À l’exécution

figatellultimate ne formate rien lui-même. `@figatellultimate/use-intl` donne des traducteurs typés par les messages générés :

```ts
import { createTranslator } from '@figatellultimate/use-intl';
import { loadMessages } from '#figatellultimate/messages';

const t = createTranslator({ locale: 'fr', messages: await loadMessages('fr') });
t('ui.folder.more', { count: 3 });
```

Dans une application Next.js, next-intl lit les mêmes messages, typés par les mêmes déclarations.

## Messages précompilés

Dans une application Next.js, chaque message peut être compilé une fois, au build : aucune page n’embarque alors l’analyseur ICU, ni le catalogue des messages. Les clés se typent avec `runtime: 'use-intl'` dans `messages` de la config.

Côté serveur, `precompiledLoader` compile les messages de chaque langue une fois par processus (`precompileMessages` pour un seul arbre), et next-intl les lit avec son moteur `format-only`, que `withPrecompiledMessages` lui donne :

```ts
// i18n/request.ts
import { precompiledLoader } from '@figatellultimate/use-intl/precompile';

// Les messages de chaque langue, compilés une fois par processus.
const precompiled = precompiledLoader(loadMessages);

export default getRequestConfig(async ({ locale }) => ({
  locale,
  // next-intl type les messages sources : il reçoit ici leur forme compilée.
  messages: (await precompiled(locale)) as unknown as Messages,
}));
```

```ts
// next.config.ts
import { withPrecompiledMessages } from '@figatellultimate/next16/config';

export default createNextIntlPlugin('./i18n/request.ts')(withPrecompiledMessages(nextConfig));
```

Les composants clients reçoivent leurs textes du serveur, déjà formatés. Ceux qui dépendent d’une valeur que seul le navigateur connaît, comme un nombre de résultats, voyagent précompilés avec leur clé :

```tsx
// Un composant serveur
<SearchStatus found={precompiled(tree, 'ui.search.found')} />;

// Le composant client
formatPrecompiled(found, locale, { count: results.length });
```

La clé type les arguments : oublier `count` ne compile pas. Une date s’affiche dans le fuseau du navigateur ; côté serveur, un style de date nommé (`{day, date, long}`) se déclare dans les `formats` de next-intl.
