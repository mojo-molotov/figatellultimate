# Next.js

`@figatellultimate/next16` traduit les données neutres de figatellultimate pour l’App Router de Next.js 16 ; `@figatellultimate/site` les calcule, sans framework. La version majeure de Next est dans le nom du paquet : une nouvelle majeure aura son propre adaptateur.

```sh npm
npm install @figatellultimate/next16 @figatellultimate/site
```

```sh pnpm
pnpm add @figatellultimate/next16 @figatellultimate/site
```

```sh yarn
yarn add @figatellultimate/next16 @figatellultimate/site
```

```sh bun
bun add @figatellultimate/next16 @figatellultimate/site
```

## Les routes : une, ou une par base

La configuration dit comment l’application route ses pages, `splitRoutes`, un choix obligatoire : chaque façon a un coût que l’autre évite.

### Une route pour toutes les pages

`splitRoutes: false`. Un catch-all facultatif par langue sert chaque entrée, page de dossier et page de terme, toutes prérendues :

```tsx
// app/[locale]/[[...url]]/page.tsx
import { findByUrl, mountedUrls, segmentsOf, urlOf } from '#figatellultimate/urls';

export const dynamicParams = false;

export function generateStaticParams() {
  return mountedUrls.map((item) => ({ locale: item.locale, url: segmentsOf(item.url, item.locale) }));
}

export default async function Page(props: PageProps<'/[locale]/[[...url]]'>) {
  const { locale, url } = await props.params;
  const found = await findByUrl(urlOf(locale, url));

  if (found === undefined) notFound();
  // found.kind : 'entry', 'folder' ou 'term'
}
```

Avec `dynamicParams = false`, une URL inconnue est une vraie 404, jamais rendue à la demande.

Un seul fichier, et n’importe quelle disposition du contenu : une page peut se trouver n’importe où, `/blog/about` compris. Le coût : Next ne peut pas savoir quel type de page la route rend, alors chaque page charge le code client de tous les types. Une page de documentation charge la pagination du blog, son tri et ses cartes.

### Une route par base

`splitRoutes: true`. Une route par base d’une collection ou des pages d’une taxonomie, la route racine servant les collections de base `''`. `routeParamsOf` donne à chaque route ses pages, leur chemin sous sa base :

```tsx
// app/[locale]/blog/[[...url]]/page.tsx
import { findByUrl, routeParamsOf, urlOf } from '#figatellultimate/urls';

export function generateStaticParams() {
  return routeParamsOf('blog');
}

export default async function Page(props: PageProps<'/[locale]/blog/[[...url]]'>) {
  const { locale, url = [] } = await props.params;
  const found = await findByUrl(urlOf(locale, ['blog', ...url]));
  // un billet ou une page de dossier du blog
}
```

Chaque page ne charge que le code client de son propre type : sur ce site, une page de documentation pèse 13 ko gzip de moins qu’avec une seule route. Les coûts : un fichier par base, et une contrainte sur le contenu. Next répond à un chemin par sa route la plus précise, alors une page sous le préfixe d’une autre route, comme une page `content/pages/blog/about.mdx` à `/blog/about`, recevrait la réponse de la route du blog, qui ne la connaît pas : une 404. `figatellultimate build` signale chacune de ces pages (`route-shadowed`), avec ses deux issues : la déplacer, ou donner une autre base à sa collection.

Chaque URL montée porte la base de sa route (`routeBase` dans `mountedUrls`). Des collections qui partagent une base partagent une route.

## Les métadonnées

`metadataOf` lit les champs que la collection a déclarés : titre, description, image, URL canonique, alternatives `hreflang` avec `x-default`, directives robots, Open Graph :

```ts
import { toNextMetadata } from '@figatellultimate/next16';
import { metadataOf } from '@figatellultimate/site';
import { metadataFields } from '#figatellultimate/urls';

export async function generateMetadata(props) {
  const found = await findByUrl(/* … */);

  return found?.kind === 'entry' ? toNextMetadata(metadataOf(found.entry, metadataFields[found.collection], site)) : {};
}
```

`site` contient l’origine et le nom du site : `{ origin: 'https://example.com', name: 'Mon site', defaultLocale: 'fr' }`. Le nom suit le titre de chaque page (`Blog · Mon site`), et la page d’accueil de chaque langue porte le nom seul ; `titleTemplate` en change la forme, `%s` y tenant la place du titre (`'%s | Mon site'`).

## Sitemap et robots

```ts
// app/sitemap.ts
export default function sitemap() {
  return toNextSitemap(sitemapOf(mountedUrls, site));
}

// app/robots.ts
export default function robots() {
  return toNextRobots(site);
}
```

Le sitemap liste chaque page indexable avec ses traductions et sa date de modification ; une page marquée `noindex` en est exclue.

## Données structurées et flux

`structuredDataOf` donne les données schema.org d’une entrée (un `BlogPosting` avec ses auteurs, une `WebPage`), `breadcrumbListOf` son fil d’Ariane ; `jsonLd` les sérialise pour un `<script type="application/ld+json">`. `rssOf` écrit le flux RSS d’une collection, par langue.

## llms.txt

Ce qu’une collection expose aux LLM ([la configuration](/docs/configuration#exposer-aux-llm)) se sert par trois routes, comme le flux : `llms.txt` par langue, `llms-full.txt`, toutes les pages dans un fichier (un ajout à la convention, que beaucoup d’outils lisent), et la version Markdown de chaque page. `mountedUrls` marque les URL exposées (`llms`) ; `@figatellultimate/site` écrit les fichiers, et l’adaptateur de l’outil de contenu le Markdown de chaque page.

| Fonction         | Ce qu’elle écrit                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `llmsTxtOf`      | Le fichier `llms.txt`, d’après la convention : un titre, un résumé, des listes de liens.                                                                                                                                                                 |
| `llmsMarkdownOf` | Le Markdown d’une page, depuis son MDX (`@figatellultimate/content-collections/llms`) : sans ce que tient `<llm-exclude>`, ni les imports, exports et expressions du MDX, chaque composant écrit en Markdown par l’application, ou réduit à son contenu. |
| `llmsFullOf`     | Le fichier `llms-full.txt`.                                                                                                                                                                                                                              |
| `markdownUrlOf`  | L’URL de la version Markdown d’une page : la sienne suivie de `.md`.                                                                                                                                                                                     |
| `exposedPagesOf` | Collecte et trie par `order` puis titre les pages exposées d’une langue (`isLlmsExposed` teste une URL dans `mountedUrls`).                                                                                                                              |

Une route ne peut pas partager le segment de la route commune : le proxy réécrit `/docs/cli.md` vers une route dédiée, dans la langue de la page (`app/[locale]/llms/[[...url]]`). Chaque page exposée renvoie à sa version Markdown et au `llms.txt` de sa langue, par `<link rel="alternate" type="text/markdown">` et `<link rel="describedby">`.

## Les agents (ARD)

Ce qu’un site offre aux agents IA se déclare d’après [Agentic Resource Discovery](https://agenticresourcediscovery.org/spec/) : un manifeste `ard.json`, à l’adresse que la convention réserve aux agents, liste ses ressources, une skill d’agent, un serveur MCP. `agentCatalogOf` de `@figatellultimate/site` l’écrit, chaque identifiant ancré au domaine du site (`urn:air:<domaine>:<nom>`). Le même document se lit aussi comme son prédécesseur, AI Catalog ; l’exemple le sert donc aux deux chemins, `ard.json` et `ai-catalog.json`, et chaque page y renvoie par `<link rel="ard">`.

Ce site y liste sa skill, `use-figatellultimate`, qui apprend à un agent à se servir de figatellultimate : [/skills/use-figatellultimate/SKILL.md](/skills/use-figatellultimate/SKILL.md). llms.txt n’y figure pas : c’est de la documentation, pas une ressource qu’un agent appelle.

## Les redirections

`figatellultimate migrate` écrit `redirects.json` quand des URL changent. Next les sert en redirections permanentes :

```ts
// next.config.ts
export default {
  redirects: async () => toNextRedirects(JSON.parse(await readFile('redirects.json', 'utf8'))),
};
```

## Les liens et les images

Les composants de `@figatellultimate/ui` lient les pages et affichent les images par les composants de l’application : enveloppez la mise en page dans `UiProvider` (`link={NextLink}`, `image={NextImage}`), ou séparément dans `LinkProvider` et `ImageProvider`. Les navigations restent côté client, et les couvertures des cartes, les avatars des auteurs et les images du contenu sont redimensionnés et servis aux formats modernes. Le `Backdrop` de `@figatellultimate/effects` reçoit `next/image` par sa prop `image`.

Une image du contenu doit connaître sa taille : `rehypeImageSizes`, de `@figatellultimate/content-collections/images`, lit au build la largeur et la hauteur de chaque image locale du dossier `public/`. Une image distante ou non mesurée reste une `<img>` ordinaire.

Pour optimiser le LCP sur ordinateur sans alourdir le premier affichage mobile ni recourir au rendu dynamique, `cardImagePriority` de `@figatellultimate/next16/images` garde les cartes au-delà du quota mobile en chargement paresseux tout en émettant un `<link rel="preload" media>` réservé aux écrans larges, avec le `srcSet` et les `sizes` exacts de `next/image`.

## Les thèmes paresseux

Pour ne pas embarquer dans le CSS initial les thèmes non actifs par défaut, `themeStylesheetRoute` de `@figatellultimate/next16/themes` sert chaque feuille de thème en route statique immuable (`/themes/<nom>.css`), en binôme avec `stylesheetBase` de `siteThemeScript` et `SiteThemePicker`.

## Les messages

next-intl formate les messages côté serveur, précompilés : `withPrecompiledMessages` de `@figatellultimate/next16/config` lui donne son moteur `format-only`, et les composants clients reçoivent leurs textes déjà formatés. Aucune page n’embarque l’analyseur ICU ni le catalogue des messages ; le détail est dans [Messages](/docs/messages).
