# Collections à facettes

Une collection à facettes filtre une liste sur plusieurs facettes, la trie et la pagine, avec tout son état dans l’URL : une vue filtrée est un lien que n’importe qui peut partager, et la vue par défaut est prérendue.

```sh npm
npm install @figatellultimate/facets @figatellultimate/facets-react react radix-ui cmdk
```

```sh pnpm
pnpm add @figatellultimate/facets @figatellultimate/facets-react react radix-ui cmdk
```

```sh yarn
yarn add @figatellultimate/facets @figatellultimate/facets-react react radix-ui cmdk
```

```sh bun
bun add @figatellultimate/facets @figatellultimate/facets-react react radix-ui cmdk
```

## Le moteur

`defineFacetedCollection` déclare les éléments, leurs facettes et leurs tris, et la taille des pages. Le moteur est pur : il lit une URL, calcule une vue et écrit l’URL suivante.

```ts
import { defineFacetedCollection } from '@figatellultimate/facets';

const engine = defineFacetedCollection({
  items: posts,
  key: (post) => post.url,
  facets: { tags: { values: (post) => post.tags }, authors: { values: (post) => post.authors, mode: 'all' } },
  sorts: {
    'date-desc': (one, other) => other.date.localeCompare(one.date),
    'title-asc': (one, other) => one.title.localeCompare(other.title),
  },
  perPage: 5,
});

const state = engine.read('?tags=release&sort=title-asc&page=2');
const { keys, total, pages, counts } = engine.view(state);
```

| Pièce                       | Rôle                                                                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `read(search)`              | L’état de n’importe quelle URL : une valeur inconnue, une page hors limites ou un lien cassé donnent un état valide, jamais une erreur. |
| `view(state)`               | Les clés visibles, le total, les pages, et le compte de chaque valeur.                                                                  |
| `transition(state, action)` | L’état suivant et son URL, pour `toggle`, `clear`, `sort` ou `page`.                                                                    |
| `write(state)`              | L’URL canonique d’un état.                                                                                                              |

La page et le tri se lisent dans `page` et `sort` de la requête ; `params: { page: 'p', sort: 'order' }` les nomme autrement, jamais comme une facette.

Une facette en mode `any` garde un élément qui porte l’une des valeurs cochées ; en mode `all`, toutes. Les facettes se combinent en ET.

### Où atterrit la page

Changer un filtre garde la place du lecteur par défaut (`keepReadingPosition`) : la page qui contient le premier billet qu’il regardait. `backToFirstPage` revient plutôt à la page 1.

## En React

`useFacetedCollection` relie le moteur à l’URL ; les composants sont sans style et accessibles :

```tsx
import { FacetOptions, FacetsReset, Pagination, SortSelect, useFacetedCollection } from '@figatellultimate/facets-react';
import { useNextUrl } from '@figatellultimate/next16/facets';

const binding = useFacetedCollection(engine, useNextUrl());

<FacetOptions binding={binding} facet="tags" labels={labels.tags} locale="en" />
<SortSelect binding={binding} labels={labels.sort} />
{binding.view.keys.map((key) => cards[key])}
<Pagination binding={binding} labels={labels.pagination} locale="en" />
```

`PageSelect` est une pagination compacte, les pages en liste déroulante, pour une barre d’outils ; la `Pagination` complète garde les liens. Chacune prend `icons` pour les liens précédent et suivant, seules affichées sur un écran étroit.

`ListingOptions` range les facettes derrière un seul bouton, l’icône de l’application (une roue crantée) et le nombre de termes choisis : son panneau garde les widgets tels quels, ↑ et ↓ passant de l’un à l’autre, pour que les contrôles d’une liste tiennent sur une ligne sur tout écran, le tri à côté de la roue. Une seule facette s’affiche à la place de la roue : un panneau ne contenant qu’une liste serait un clic pour rien.

Chaque texte lu à voix haute peut différer de celui qu’on voit, quand celui-ci se lit mal : `spoken` de `SortSelect` lit « Ordre alphabétique » pour `A → Z` (la liste ouverte l’affiche aussi, le nom d’une option contenant son texte visible), `spoken` de `PageSelect` lit « Page 3 sur 10 » pour `3 / 10`, et `unit` de `FacetOptions` fait entendre « Harpe 17 articles » sous « Harpe 17 ».

`useNextUrl` change l’URL par l’API History, intégrée par le routeur de Next : aucune requête serveur par filtre. Hors de Next, `useHistoryUrl` fait de même.

Le hook ne donne que des clés : l’application rend ses cartes une fois, côté serveur, et montre celles que la vue contient.

### Les listes paginées

Une liste dont les pages sont prérendues (`perPage` de `folderPages`) envoie chaque page avec sa seule tranche : `/blog/news/page/2` contient ses cinq articles, quelle que soit la taille du blog. Ses pages par défaut vivent dans le chemin, atteintes par le routeur. Un filtre ou un tri reste dans la requête (`/blog/news?tags=bot`) et a besoin de tous les articles de la liste, de n’importe quelle page : le navigateur le calcule à partir de l’index de la liste, un JSON statique chargé au premier filtre ou tri, jamais avec la page.

`usePagedCollection` passe l’URL de la première page de la liste et orchestre le tout : la tranche de la page tant que l’index n’est pas nécessaire, ses pages par défaut atteintes par la seule URL, l’index préchargé quand le lecteur se dirige vers un filtre (`prefetch`, au pointeur ou au focus), un filtre choisi tôt appliqué dès qu’il arrive. `createIndexLoader` vérifie l’index par votre schéma avant de le lire, et ne le charge qu’une fois par liste.

```tsx
const load = createIndexLoader((json) => v.parse(Index, json));
const { binding, index, prefetch } = usePagedCollection({
  engine: postsEngine,
  items: slice,
  paged: { page: folder.page, pages: folder.pages, total: folder.entries.length },
  load: () => load(indexUrl),
  url: useNextUrl({ first: folder.first }),
});
```

La configuration déclare où vivent les index : `index` dans `folderPages` pour les listes d’une collection, dans les `pages` d’une taxonomie pour ses termes. Chaque page d’une liste paginée porte alors l’URL de son index (`folder.index`, `page.index`), la même sur toutes ses pages, et le code généré liste les listes à indexer (`blogListingIndexes()`, `authorsListingIndexes()`).

```ts
folderPages: { levels: ['category', 'subcategory'], perPage: { subcategory: 5 }, index: 'listing' },
```

L’index est une route statique par liste et par langue, produite par `listingIndexRoute` de `@figatellultimate/next16/listing-index`, qui prend ces listes, les paramètres de route de chacune, et `build`, son contenu : l’élément de chaque article, ce que le moteur filtre et trie, et les données de sa carte, pour que le navigateur dessine les cartes des pages qu’il n’a pas. Seul `build` revient à l’application.

```ts
// app/[locale]/listing/[[...folder]]/route.ts: /listing/news/bot, /en/listing/news/bot
export const dynamic = 'force-static';
export const dynamicParams = false;
export const { GET, generateStaticParams } = listingIndexRoute({
  listings: blogListingIndexes,
  params: (folder) => ({ locale: folder.locale, folder: Object.values(folder.segments) }),
  build,
});
```

L’exemple en a deux : `listing/[[...folder]]` pour les articles d’une sous-catégorie, `author-listing/[...term]` pour ceux d’un auteur, toutes sous-catégories confondues. Un index coûte une cinquantaine d’octets gzip par article (le test de charge le mesure).

À côté de son index, une liste a des lots de pages : les pages de sa vue par défaut, dix par dix (`batchesOf`), chacun un petit fichier statique à `<index>/pages/<première page>`, produit par la même route (son option `pages`). `usePagedCollection` charge le lot de la page courante dès que la page est au repos, puis le suivant ou le précédent près de ses bords ; une page que son lot contient s’affiche aussitôt, seule l’adresse bougeant, et toute autre passe par le serveur. Le coût par visite reste celui d’un lot, environ deux kilo-octets gzip, quelle que soit la longueur de la liste : le test de charge mesure un clic sur suivant sous les 50 ms avec un serveur à 300 ms, contre 360 ms par le serveur.

```ts
usePagedCollection({ …, batches: { load: (from) => loadBatch(`${index}/${batchPath(from).join('/')}`) } });
```

`pageItems` et `batchItems` de `@figatellultimate/facets` donnent les éléments d’une page et ceux d’un lot, pour son `build`. Dans une page prérendue, `NextUrlBoundary` de `@figatellultimate/next16/facets` rend la liste depuis sa page d’arrivée tant que l’adresse n’est pas lue, puis depuis l’adresse : les liens de pagination sont réels dans le HTML. Le sélecteur de langue suit la page affichée par un lot : `usePagedLocaleLinks`, avec la liste dans chaque langue (`listingLocalesOf` de `@figatellultimate/site`).

Les pages de dossiers ont leurs lots elles aussi : le blog et une catégorie, leurs sections de sous-dossiers dix pages par dix. Chaque dossier paginé porte l’URL de ses lots sous le même préfixe que les index (`folder.batches` : `/listing`, `/listing/news`), le code généré liste ces dossiers (`blogFolderBatches()`), et la route les sert par `pages.listings` ; d’où le catch-all facultatif, pour `/listing/pages/1`. Un dossier n’a rien à filtrer : `usePagedCollection` s’y passe d’index (`load` absent).

Hors de Next, `pagedHref` et `pagedSearch` de `@figatellultimate/facets` font passer une vue à cet emplacement et inversement. Avec un segment de page autre que `page` (`urls.page`) ou un paramètre de page propre au moteur (`params.page`), `useNextUrl`, `NextUrlBoundary` et `usePagedLocaleLinks` les prennent en `segment` et `param` : le `pageSegment` généré de `#figatellultimate/urls` donne le premier.

### Lots de sections adaptatifs

Pour une liste statique **sans filtres ni tri** (comme `/docs`, `/blog` ou une page de catégorie, à ordre fixe), les cartes ou sections peuvent être découpées en lots JSON statiques (`splitSectionBatches` et `pagedSectionsOf` de `@figatellultimate/site` ou les lots `folder.batches`, servis par `listingIndexRoute`), puis affichées avec `ResponsiveBatchList` et `BatchPagination` (ou les hooks `useResponsiveBatches` et `useBatchPagination`) de `@figatellultimate/facets-react` : défilement progressif (`IntersectionObserver`) sur téléphone et pagination classique (`PageSelect` + `Pagination`) sur ordinateur, en partageant le même cache de lots et le même HTML prérendu. Les listes filtrables ou triables gardent quant à elles `usePagedCollection` et la pagination sur tous les écrans, afin de préserver les URL partageables et la position de lecture.
