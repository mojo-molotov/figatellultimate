# Recherche

La recherche tourne dans le navigateur du lecteur, sur un index construit depuis le HTML de votre site avec Pagefind : ni serveur, ni service externe. Chaque langue a son propre index, avec sa propre racinisation.

## L’indexation

Après le build du framework, `figatellultimate search` indexe le HTML construit de chaque entrée montée et cherchable :

```sh npm
npx figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

```sh pnpm
pnpm figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

```sh yarn
yarn figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

```sh bun
bunx figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

`--locale-folders` sert aux builds qui écrivent chaque langue dans son propre dossier, celle par défaut comprise, comme next-intl. Une collection qui déclare `searchable: false` est exclue. Le texte indexé est l’élément marqué `data-pagefind-body` : la navigation, le pied de page et les listes de pages restent hors des résultats.

Avec un adaptateur de déploiement (celui de Vercel), Next écrit les pages prérendues ailleurs, sous un dossier haché par route : `prerenderedPages` de `@figatellultimate/next16/build` donne le dossier qui les contient, avec ou sans adaptateur, et `copyIntoOutput` copie l’index dans la sortie de l’adaptateur, que le déploiement sert.

## Le client

`createSearch` interroge l’index d’une langue, paresseusement : rien ne se charge avant la première requête.

```ts
import { createSearch } from '@figatellultimate/search';

const search = createSearch({ locale: 'en', collections: ['pages', 'blog'] });
const page = await search.query('locale', { sort: 'date-desc' });

if (page?.status === 'done') console.log(page.results, await page.more?.());
```

Les résultats arrivent par lots (`more`), chacun avec son URL, son titre, son extrait, sa collection et sa date. Une requête plus courte que la longueur minimale répond `too-short`, sans rien charger.

### Les tris

`relevance` (par défaut), `title-asc`, `title-desc`, `date-desc` et `date-asc` ; les pages sans date viennent après celles qui en ont, dans les deux sens.

## Le champ de recherche

`@figatellultimate/search-react` donne un champ et une fenêtre de recherche, sans style et accessibles, ouverts depuis la barre de navigation ou avec ⌘K / Ctrl+K :

```tsx
import { SearchDialog } from '@figatellultimate/search-react';

<SearchDialog
  search={search}
  labels={labels}
  boxLabels={boxLabels}
  locale="en"
  onNavigate={(url) => router.push(url)}
/>;
```

Chaque résultat est nommé par son titre, son emplacement et sa date, courts à entendre d’une flèche à l’autre ; son extrait est sa description, lue après une pause. `trail` donne l’emplacement : une liste d’étapes, dessinées avec des chevrons qu’un lecteur d’écran ne dit pas, ou un texte tel quel. `pause` est ce qu’on entend entre ces parties sans le voir, une virgule par exemple, et `spoken` les noms lus des tris, comme pour `SortSelect`.
