# Search

The search runs in the reader’s browser, over an index built from your site’s HTML with Pagefind: no server, no external service. Each language has its own index, with its own stemming.

## Indexing

After the framework’s build, `figatellultimate search` indexes the built HTML of every mounted, searchable entry:

```sh npm
npx figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

```sh pnpm
pnpm figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

```sh yarn
yarn figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

```sh bun
bunx figatellultimate search --site .next/server/app --out public/pagefind --locale-folders
```

`--locale-folders` is for builds that write every language in its own folder, the default one included, as next-intl does. A collection declaring `searchable: false` is left out. The indexed text is the element marked `data-pagefind-body`: the navigation, the footer and the lists of pages stay out of the results. Its code blocks are left out, and the code tabs’ names with them: an excerpt is the page’s text, never a command.

With a deployment adapter (Vercel’s), Next writes the prerendered pages elsewhere, under a folder hashed by route: `prerenderedPages` of `@figatellultimate/next16/build` gives the folder holding them, with an adapter or without, and `copyIntoOutput` copies the index into the adapter’s output, which the deployment serves.

## The client

`createSearch` queries the index of one language, lazily: nothing loads before the first query.

```ts
import { createSearch } from '@figatellultimate/search';

const search = createSearch({ locale: 'en', collections: ['pages', 'blog'] });
const page = await search.query('locale', { sort: 'date-desc' });

if (page?.status === 'done') console.log(page.results, await page.more?.());
```

Results arrive by batches (`more`), each with its URL, title, excerpt, collection and date. A query shorter than the minimum length answers `too-short`, without loading anything.

### Sorts

`relevance` (the default), `title-asc`, `title-desc`, `date-desc` and `date-asc`; undated pages come after dated ones, both ways.

## The search box

`@figatellultimate/search-react` gives a search box and a search dialog, unstyled and accessible, opened from the navbar or with ⌘K / Ctrl+K:

```tsx
import { SearchDialog } from '@figatellultimate/search-react';

<SearchDialog
  search={search}
  labels={labels}
  boxLabels={boxLabels}
  locale="en"
  onNavigate={(url) => router.push(url)}
/>;
```

Each result is named by its title, its place and its date, short to hear from one arrow to the next; its excerpt is its description, read after a pause. `trail` gives the place: a list of steps, drawn with chevrons a screen reader does not say, or a text as is. `pause` is what is heard between those parts without being seen, a comma for instance, and `spoken` the sorts’ names read aloud, as for `SortSelect`.

In the field, ↓ on the last result reaches “See more”, ↑ from it comes back to the last one, and ↑ on the first one leaves the field alone. `labels.shortcut` shows the shortcut after the button’s label, the reader’s keys (⌘K on an Apple device, Ctrl K elsewhere), marked before the first paint by `searchShortcutScript` of `@figatellultimate/search-react/scripts`; `labels.spoken.placeholder` gives the field a text read instead of its placeholder, which an ellipsis makes read badly.
