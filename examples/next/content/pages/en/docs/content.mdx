# Writing content

Content is MDX files in folders. The path of a file is its structure: no frontmatter says which category or language it belongs to, so nothing can contradict the folders.

## A file and its URL

With the grammar `[segment('category'), locale({ optional: true }), slug()]` under the base `blog`:

| File                              | Language | URL                    |
| --------------------------------- | -------- | ---------------------- |
| `content/blog/news/launch.mdx`    | default  | `/blog/news/launch`    |
| `content/blog/news/en/launch.mdx` | `en`     | `/en/blog/news/launch` |

The two files are the same entry in two languages: each links the other, for the language switcher, the `hreflang` alternates and the sitemap.

### Names

Folder and file names are lowercase letters, digits and dashes. `Bad Name.mdx` is an error suggesting `bad-name.mdx`. Two files differing only by case are an error too: macOS and Windows see them as one.

### index.mdx

An `index.mdx` is its folder’s page: `content/pages/docs/index.mdx` is `/docs`. A collection may forbid it where a folder page is generated instead.

## Languages

In the implicit notation, the default, a file without a language folder is in the default language. In the explicit notation, every language has its folder. `figatellultimate migrate notation explicit` moves every file from one to the other, and writes the redirects of the URLs that change.

A missing translation is not an error: the page exists in the languages it was written in, and the generated types know which ones.

## Frontmatter

The frontmatter is checked by the collection’s schema, in the content tool: any Standard Schema library, such as valibot or zod. A missing or invalid field is reported on its file, the schema’s message included.

```mdx
---
title: 'Launch'
description: 'What the first version brings.'
date: 2026-03-01
tags: [release]
---

# Launch
```

### Translations

A translation writes only what differs from the other version. The collection lists the fields its translations share, `shared`: a translation that leaves one of them out takes the default language’s value, and one it writes is its own. A file can also take every field it leaves out from another language, with `inherit:`.

```ts
blog: defineCollection({ …, shared: ['featuredPictureUrl', 'date', 'authors', 'tags'] }),
```

```mdx
---
title: 'Launch'
description: 'What the first version brings.'
---
```

The completed frontmatter is checked by the schema, as a file’s: a required shared field with no version in the default language to take it from is an error, as is an `inherit:` naming a language with no version of the page.

## Drafts and test content

A collection declaring `draft: 'draft'` reads that boolean field: drafts are built in development, left out of production. `testOnly` does the same by key, for content that only tests need.

## Reserved entries

`reserved: ['pricing']` leaves an entry out of the shared route: an application page serves it, and still reads it, typed, through its getter.

## Taxonomy references

A field declared in `references` holds terms of a taxonomy: `tags: [release]`. An unknown term is an error suggesting the closest one; a term repeated in a field is an error too.

## Diagnostics

Every problem says where it is, why, and how to fix it, and `figatellultimate build` lists them all at once, never only the first:

```text
content/blog/news/Bad Name.mdx
  ✖ file name "Bad Name" breaks the naming rule (lowercase letters, digits and dashes)
    → rename it to "bad-name"
```

An error stops the build, leaving the last valid generated code in place; a warning, such as a reservation matching no entry, does not. An info only tells what the build chose on its own, such as a folder showing its newest entry’s image.
