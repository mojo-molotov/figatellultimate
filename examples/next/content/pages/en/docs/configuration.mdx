# Configuration

Everything is declared once, in `figatellultimate.config.ts`: the locales, the collections and their path grammar, the taxonomies, the navigation and the content source. The configuration is data: every `define…` function validates its part where it is written, and an invalid declaration fails at once, saying what to fix.

```ts
import { createContentCollectionsSource } from '@figatellultimate/content-collections';
import { defineCollection, defineConfig, defineLocales, locale, rest, slug } from '@figatellultimate/core';

export default defineConfig({
  locales: defineLocales({ list: { fr: { label: 'Français' }, en: { label: 'English' } }, default: 'fr' }),
  collections: {
    pages: defineCollection({ entry: 'page', base: '', grammar: [locale({ optional: true }), rest('path'), slug()] }),
  },
  source: createContentCollectionsSource({ configPath: 'content-collections.ts', projectRoot: import.meta.dirname }),
});
```

## Locales

`defineLocales` lists the site’s languages, with their label and, when needed, their writing direction, and names the default one. Adding a language is one more line here, then following the diagnostics: every missing translation is reported.

### URLs

`urls` sets the URL strategy, used everywhere: the default language unprefixed (`implicit`, the default) or prefixed like the others (`explicit`), and trailing slashes.

```ts
defineConfig({ /* … */ urls: { defaultLocale: 'explicit', trailingSlash: false } });
```

## Collections

A collection gathers documents sharing a path shape. Its `entry` names the generated API (`blogPost` gives `getBlogPost`), its `base` prefixes its URLs, and its grammar says what each folder means:

```ts
const blog = defineCollection({
  entry: 'blogPost',
  base: 'blog',
  grammar: [segment('category'), segment('subcategory'), locale({ optional: true }), slug()],
});
```

From `news/releases/first.mdx`, figatellultimate infers the category, the subcategory, the language and the URL `/blog/news/releases/first`. One folder too many, an invalid name or two files at one URL are errors naming the file at fault.

### The grammar

| Part                            | Meaning                                                          |
| ------------------------------- | ---------------------------------------------------------------- |
| `segment('name')`               | One folder, its value named.                                     |
| `rest('name')`                  | Any depth of folders, for free-form trees such as documentation. |
| `locale({ optional: true })`    | The language folder; optional: the default language may omit it. |
| `slug()`                        | The file name, always last.                                      |
| `join('-', 'category', 'slug')` | In `route`: two parts joined into one URL segment.               |

### Options

| Option                                        | Effect                                                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `route`                                       | How the URL is composed from the grammar’s parts.                                                   |
| `reserved`                                    | Keys served by a dedicated route instead of the shared one: still typed and readable.               |
| `indexForbiddenUnder`, `indexForbiddenAtRoot` | Where an `index.mdx` is not allowed.                                                                |
| `draft`                                       | The boolean field marking drafts, left out of production builds.                                    |
| `testOnly`                                    | Keys of test content, left out of production builds.                                                |
| `shared`                                      | Fields translations take from the default language when they leave them out.                        |
| `references`                                  | Frontmatter fields referencing a taxonomy.                                                          |
| `metadata`                                    | The fields holding the title, description, image, dates, robots, canonical URL and order.           |
| `llms`                                        | What it exposes to LLMs: its keys, as `reserved`, and the boolean field leaving a page out (below). |
| `searchable`                                  | Whether the local search indexes the collection (default `true`).                                   |
| `folderPages`                                 | Folders with a page of their own (below).                                                           |
| `mounted`                                     | `false`: no page at all, read through its getters only (a taxonomy’s content).                      |
| `messages`                                    | Fields each folder must have in every language’s messages.                                          |

### Metadata

The collection names its frontmatter fields: metadata, sitemap, feeds and sorts read them with no code of the collection’s own. `order` places a page among its siblings, lower first, in the navigation, its section’s list and the previous and next links; pages without one come after, by title.

```ts
metadata: { title: 'title', description: 'description', image: 'cover', publishedTime: 'date', modifiedTime: 'updated' },
```

### Folder pages

`folderPages` gives the folders of some levels a page, mounted like an entry: a blog lists its categories, a category its subcategories with their latest posts, with no hand-written route.

```ts
folderPages: { root: true, levels: ['category', 'subcategory'], preview: 2, images: { news: '/covers/news.jpeg' } },
```

`perPage` splits a level's folder pages, or the root's, into pages of that many items: subfolders, or entries for a level with no subfolder. Each further page is a page of its own, at `…/page/N`, prerendered with its slice, in the sitemap and translated; a locale with fewer entries has fewer pages.

```ts
folderPages: { root: true, levels: ['category', 'subcategory'], perPage: { root: 6, subcategory: 5 } },
```

`index` gives each paginated listing of entries an index, at `/<index>/<its segments>` in each language: every entry a filter or a sort needs, fetched by the browser instead of the page (see the faceted collections). A taxonomy’s `pages` take it too, for its terms; both need a page size.

A folder page has no frontmatter: its SEO is declared like an entry's `metadata`, but naming a field of the folder's messages. `metadata.description` gives every folder page its meta description; each level with pages must declare that field in its `messages`, or the config is refused. The collection's own page declares its fields in `messages.$root`, at `content.blog.$`, and follows the same rule: with `folderPages.root`, it must declare that field too.

```ts
messages: { $root: ['description'], category: ['title', 'description'], subcategory: ['title', 'description'] },
folderPages: { root: true, levels: ['category', 'subcategory'], metadata: { description: 'description' } },
```

### Exposing to LLMs

`llms` says what a collection exposes to LLMs, after the [llms.txt](https://llmstxt.org) convention: an `llms.txt` file per language listing its pages, and each page as Markdown, at its URL followed by `.md`. Its keys are named as `reserved`’s, a key or `prefix/*` for its descendants; `exclude` names the boolean frontmatter field leaving a page out.

```ts
pages: defineCollection({
  entry: 'page',
  base: '',
  grammar: [locale({ optional: true }), rest('path'), slug()],
  llms: { include: ['docs', 'docs/*'], exclude: 'llmExclude' },
}),
```

A whole page leaves itself out by its frontmatter:

```mdx
---
title: 'Internal notes'
llmExclude: true
---
```

A passage leaves itself out with the `<llm-exclude>` tag: the page shows it, without the tag, and its Markdown version leaves it out. A blank line around its content, so that it stays Markdown:

```mdx
<llm-exclude>

The package manager you pick in a tab holds for the whole documentation.

</llm-exclude>
```

MDX becomes Markdown: its imports, exports and expressions are gone, comments included, and a component is reduced to its content. The app can write a component as Markdown, as it renders it with React, from its props (their literal values) and its content, already converted:

```ts
llmsMarkdownOf(entry.body, {
  components: {
    Callout: ({ type }, content) => `> **${String(type)}** ${content}`,
  },
});
```

The generated code marks every exposed URL (`llms` in `mountedUrls`); the app serves the files through its routes ([Next.js](/en/docs/nextjs#llmstxt)).

## Taxonomies

Tags and authors are closed lists, declared once with `defineTaxonomy`. The frontmatter references them by key, and an unknown key is an error suggesting the closest one. A term may carry pure data (an avatar), require message fields (a name, a bio), have a page listing its entries, and a long text of its own:

```ts
authors: defineTaxonomy(
  { ada: { avatar: '/authors/ada.svg' } },
  { messages: ['name', 'bio'], pages: { base: 'authors' }, content: 'authorBios' },
),
```

`content` names an unmounted collection whose entries are keyed by term: `content/authors/ada.mdx` is Ada’s long bio, shown on her page. It is optional, per term and per language.

Likewise, `pages.metadata.description` names the messages field that describes each term page for its SEO, e.g. an author's bio: `pages: { base: 'authors', metadata: { description: 'bio' } }`. That field must be one of its `messages`.

## Navigation

`navigation` says which collections appear in the navbar, in which order and how many levels deep. A folder added to the content appears by itself, in every language.

```ts
navigation: [
  { collection: 'pages', depth: 1, menus: false },
  { collection: 'blog', depth: 2, label: 'nav.blog' },
],
```

## Images

The build checks every local image of the content: an entry’s metadata image, the folders’ (`folderPages.images`) and those of its text. An image missing from the public folder is an error, `missing-image`, naming the file and its field and suggesting the closest file: nothing is written, no page shows a broken image. `publicDirectory` names that folder, `public` by default. A folder shown with an image that declares none in `folderPages.images` shows its newest entry’s: the build lists each one, as an info.

```ts
export default defineConfig({ publicDirectory: 'static', locales, collections, source });
```
