# Next.js

`@figatellultimate/next16` maps figatellultimate’s neutral data onto the Next.js 16 App Router; `@figatellultimate/site` computes it, framework-free. The major version of Next is in the package’s name: a new major gets its own adapter.

```sh npm
npm install @figatellultimate/next16 @figatellultimate/site
```

```sh pnpm
pnpm add @figatellultimate/next16 @figatellultimate/site
```

```sh yarn
yarn add @figatellultimate/next16 @figatellultimate/site
```

```sh bun
bun add @figatellultimate/next16 @figatellultimate/site
```

## Routes: one, or one per base

The config states how the app routes its pages, `splitRoutes`, a required choice: each way has a cost the other avoids.

### One route for every page

`splitRoutes: false`. An optional catch-all per language serves every entry, folder page and term page, all prerendered:

```tsx
// app/[locale]/[[...url]]/page.tsx
import { findByUrl, mountedUrls, segmentsOf, urlOf } from '#figatellultimate/urls';

export const dynamicParams = false;

export function generateStaticParams() {
  return mountedUrls.map((item) => ({ locale: item.locale, url: segmentsOf(item.url, item.locale) }));
}

export default async function Page(props: PageProps<'/[locale]/[[...url]]'>) {
  const { locale, url } = await props.params;
  const found = await findByUrl(urlOf(locale, url));

  if (found === undefined) notFound();
  // found.kind: 'entry', 'folder' or 'term'
}
```

With `dynamicParams = false`, an unknown URL is a real 404, never rendered on demand.

One file, and any layout of the content: a page may sit anywhere, `/blog/about` included. The cost: Next cannot know which kind of page the route renders, so every page loads the client code of every kind. A documentation page loads the blog's pagination, its sort and its cards.

### A route per base

`splitRoutes: true`. A route per base of a collection or of a taxonomy's pages, the root one serving the collections based at `''`. `routeParamsOf` gives each route its pages, their path below its base:

```tsx
// app/[locale]/blog/[[...url]]/page.tsx
import { findByUrl, routeParamsOf, urlOf } from '#figatellultimate/urls';

export function generateStaticParams() {
  return routeParamsOf('blog');
}

export default async function Page(props: PageProps<'/[locale]/blog/[[...url]]'>) {
  const { locale, url = [] } = await props.params;
  const found = await findByUrl(urlOf(locale, ['blog', ...url]));
  // a post or a folder page of the blog
}
```

Each page loads only the client code of its own kind: on this site, a documentation page weighs 13 kB gzip less than with one route. The costs: a file per base, and a constraint on the content. Next answers a path from its most specific route, so a page under another route's prefix, such as a page `content/pages/blog/about.mdx` at `/blog/about`, would be answered by the blog's route, which does not know it: a 404. `figatellultimate build` reports each such page (`route-shadowed`), with its two ways out: move it, or give its collection another base.

Each mounted URL carries its route's base (`routeBase` in `mountedUrls`). Collections sharing a base share a route.

## Metadata

`metadataOf` reads the fields the collection declared: title, description, image, canonical URL, `hreflang` alternates with `x-default`, robots directives, Open Graph:

```ts
import { toNextMetadata } from '@figatellultimate/next16';
import { metadataOf } from '@figatellultimate/site';
import { metadataFields } from '#figatellultimate/urls';

export async function generateMetadata(props) {
  const found = await findByUrl(/* … */);

  return found?.kind === 'entry' ? toNextMetadata(metadataOf(found.entry, metadataFields[found.collection], site)) : {};
}
```

`site` holds the origin and the name of the site: `{ origin: 'https://example.com', name: 'My site', defaultLocale: 'en' }`. The name follows every page's title (`Blog · My site`), and each locale's home page bears the name alone; `titleTemplate` changes its form, `%s` standing for the title (`'%s | My site'`).

## Sitemap and robots

```ts
// app/sitemap.ts
export default function sitemap() {
  return toNextSitemap(sitemapOf(mountedUrls, site));
}

// app/robots.ts
export default function robots() {
  return toNextRobots(site);
}
```

The sitemap lists every indexable page with its translations and its modification date; a page marked `noindex` is left out.

## Structured data and feeds

`structuredDataOf` gives an entry’s schema.org data (a `BlogPosting` with its authors, a `WebPage`), `breadcrumbListOf` its breadcrumb; `jsonLd` serializes them for a `<script type="application/ld+json">`. `rssOf` writes a collection’s RSS feed per language.

## llms.txt

What a collection exposes to LLMs ([the configuration](/en/docs/configuration#exposing-to-llms)) is served by three routes, as the feed is: `llms.txt` per language, `llms-full.txt`, every page in one file (an addition to the convention, which many tools read), and each page’s Markdown version. `mountedUrls` marks the exposed URLs (`llms`); `@figatellultimate/site` writes the files, and the content tool’s adapter each page’s Markdown.

| Function         | What it writes                                                                                                                                                                                                                            |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `llmsTxtOf`      | The `llms.txt` file, after the convention: a title, a summary, lists of links.                                                                                                                                                            |
| `llmsMarkdownOf` | A page’s Markdown, from its MDX (`@figatellultimate/content-collections/llms`): without what `<llm-exclude>` holds, nor MDX’s imports, exports and expressions, each component written as Markdown by the app, or reduced to its content. |
| `llmsFullOf`     | The `llms-full.txt` file.                                                                                                                                                                                                                 |
| `markdownUrlOf`  | The URL of a page’s Markdown version: its own followed by `.md`.                                                                                                                                                                          |
| `exposedPagesOf` | Collects and sorts a locale’s exposed pages by `order` then title (`isLlmsExposed` checks a URL in `mountedUrls`).                                                                                                                        |

A route cannot share the shared route’s segment: the proxy rewrites `/docs/cli.md` to a dedicated route, in the page’s language (`app/[locale]/llms/[[...url]]`). Each exposed page links its Markdown version and its language’s `llms.txt`, with `<link rel="alternate" type="text/markdown">` and `<link rel="describedby">`.

## Agents (ARD)

What a site offers AI agents is declared after [Agentic Resource Discovery](https://agenticresourcediscovery.org/spec/): a manifest at `/.well-known/ard.json` lists its resources, an agent skill, an MCP server. `agentCatalogOf` of `@figatellultimate/site` writes it, each identifier anchored to the site’s domain (`urn:air:<domain>:<name>`). The same document reads as its predecessor, AI Catalog, too; the example serves it at both paths, `ard.json` and `ai-catalog.json`, and every page points to it with `<link rel="ard">`.

This site lists its skill there, `use-figatellultimate`, which teaches an agent to use figatellultimate: [/skills/use-figatellultimate/SKILL.md](/skills/use-figatellultimate/SKILL.md). llms.txt is not in it: it is documentation, not a resource an agent calls.

## Redirects

`figatellultimate migrate` writes `redirects.json` when URLs change. Next serves it as permanent redirects:

```ts
// next.config.ts
export default {
  redirects: async () => toNextRedirects(JSON.parse(await readFile('redirects.json', 'utf8'))),
};
```

## Links and images

`@figatellultimate/ui`’s components link pages and render images through the application’s components: wrap the layout in `UiProvider` (`link={NextLink}`, `image={NextImage}`), or separately in `LinkProvider` and `ImageProvider`. Navigations stay client-side, and cards’ covers, authors’ avatars and content images are resized and served in modern formats. `@figatellultimate/effects`’ `Backdrop` takes `next/image` through its `image` prop.

A content image must know its size: `rehypeImageSizes`, from `@figatellultimate/content-collections/images`, reads at build time the width and height of every local image in the `public/` folder. A remote or unmeasured image stays a plain `<img>`.

To optimize desktop LCP without weighing down mobile first paint or opting into dynamic rendering, `cardImagePriority` from `@figatellultimate/next16/images` keeps cards past the mobile count lazy in the DOM while emitting a desktop-only `<link rel="preload" media>` carrying `next/image`’s exact `srcSet` and `sizes`.

## Lazy themes

To keep non-default theme stylesheets out of the initial CSS bundle, `themeStylesheetRoute` from `@figatellultimate/next16/themes` serves each theme stylesheet as an immutable static route (`/themes/<name>.css`), paired with `stylesheetBase` on `siteThemeScript` and `SiteThemePicker`.

## Messages

next-intl formats the messages on the server, precompiled: `withPrecompiledMessages` from `@figatellultimate/next16/config` gives it its `format-only` runtime, and client components receive their texts already formatted. No page ships the ICU parser nor the catalog of messages; the details are in [Messages](/en/docs/messages).
